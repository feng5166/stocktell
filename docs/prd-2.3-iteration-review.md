## 0. Review 结论(现状底图)

产品公式 `事件输入 × 产业链图谱 × 多跳推理 × 资产映射 × 证据验证` 五个变量的兑现度:

| 变量 | 现状 | 缺口 |
|---|---|---|
| 事件输入 | 每日 8 条四段式事件卡 + 实时深读 | **无结构化事件专篇**(ReasoningChain 只到链级 daily) |
| 产业链图谱 | 4 条链 / 202 只票 / StockChainRelation 统一 | 覆盖面 = 激活漏斗最硬天花板;池外票直接 miss |
| 多跳推理 | insight 骨架 + 每日 daily,References 就近可见 | 事件级多跳缺失(同上) |
| 资产映射 | 关系分级全站统一,验证点已展示 | 验证点是静态展示,无跟踪/提醒 |
| 证据验证 | /track 全局关系验证统计 | **复盘不回流**:不落到具体推理链/关系档,置信度无校准 |

留存与增长侧:邮件早报 `EMAIL_DIGEST_PAUSED=1`(发件域问题,D1 主通道断);裂变 P0(情绪卡)方案定稿近一月未开工;webpush/微信桥可用但覆盖窄(iOS 微信内 webpush 不可用;ClawBot 单机单点)。

**2.3 主题一句话:把内核补完(事件端 + 历史端),把留存主通道接回来,跑通第一个增长实验。**

## 2. P0-1 事件专篇(insight M2)

### 2.1 背景与问题

- PRODUCT-CORE §10 定义的 P0 主展示页是**推理链详情页(事件级)**,§12 优先级第一条也是它;但当前 `/insight/[slug]` 全部是链级 daily,`src/lib/insight-pipeline/` 无 `kind: "event"` 实现(schema 有预留,生成/路由/审核均未做)。
- 事件卡现有的"拆开这条事件"是一次性实时 LLM 深读:不落库、不结构化、不可分享、不可复盘、无 SEO 沉淀——正是 PRODUCT-CORE §13 警告的"AI 长文"形态。
- 后果:分享传播缺最强素材(事件天然比链有话题性);SEO 缺事件长尾页;M3 的"历史同类复盘"没有挂靠对象。

### 2.2 目标与非目标

**目标**:触发条件命中时,自动生成结构化事件专篇(完整 ReasoningChain:事件 → 多跳 → 热力 → 国内映射 → 每跳 references),经审核后发布到 `/insight/evt/[slug]`,首页事件卡挂"看这件事的完整传导"入口。

**非目标(2.3 不做)**:逐事件成篇(维持 D1 拍板:按触发,不是每条事件都出);事件页评论/互动;历史同类复盘区(挂 P1-1 的钩子位即可,数据到了自动亮)。

### 2.3 方案要点

- **触发线沿用 M2 拍板 D3**:|隔夜|≥5% 或同链 ≥3 触发共振,数值配置化。预期频率:每周 1-3 篇,不是日更。
- **数据结构复用 `src/data/insight-chains.ts` 的 `InsightChain`**,生成侧补 `generated: true` + 触发事件元信息(triggerEventIds / triggerCode / 触发类型),落 `InsightDoc`(`kind: "event"`,slug 按 M1 约定 `evt-{date}-{triggerCode}`),生命周期与护栏(四道)完全复用 daily 管线。
- **审核档位**:事件专篇含新股票映射的概率高,**全审**(D2 口径),飞书通知复用。
- **页面**:`/insight/evt/[slug]`,信息架构照搬 PRODUCT-CORE §10 推理链详情页定义 + 三层表达原则(人话结论 → 产业链解释 → 专业依据);References 就近可见组件(`EvidencePanel` + `matchReferences`)直接复用。
- **入口**:首页事件卡命中已发布专篇时,主按钮从"看这条链怎么传导"升级为"看这件事的完整传导";链页"最近触发事件"区列出关联专篇;情境追问(insight-chat)上下文注入事件专篇。
- **SEO(P2-4 并入本期做掉)**:标题模板「{事件} 会影响 A 股哪些产业链?传导路径与映射解读 | StockTell」;结构化数据(Article);事件页 ↔ 链页 ↔ 个股页内链;归档可爬。

### 2.4 合规(铁律逐条)

- 铁律 1:事件专篇=推理不是新闻转述,无传导内容不成篇(护栏已有空判断拦截)。
- 铁律 2:每跳 references + 置信度,无强证据标"推理假设·待验证"(复用现有护栏)。
- 铁律 3:禁词表(`prd-home-reasoning-2.0.md` §9.2)+ 零数字闸(`hasSpecificMove`)+ DISCLAIMER 常量,三道全走;个股映射一律"关系分级说明性示例"口径。

### 2.5 验收标准

- [ ] 触发命中 → 草稿生成 → 护栏 → 飞书 → 人审发布,全链路 ≤ 1 交易日
- [ ] 事件页三层结构齐备,每跳可展开依据,首屏无禁词、无术语主语言
- [ ] 首页事件卡入口按"有无专篇"正确切换,无专篇不出死链
- [ ] 埋点:`evt_insight_view{slug,source}` / `evt_insight_ref_expand` / 首页入口 CTR
- [ ] SEO:事件页可被收录,og:image 有(先静态品牌图)

## 3. P0-2 邮件通道恢复 + 触达健康度看板

### 3.1 背景

- `EMAIL_DIGEST_PAUSED=1` 起因是发件域失效(`src/lib/digest.ts:246`、`src/lib/mailer.ts:8`);邮件是唯一"自选个性化早已就绪、恢复即生效"的通道。
- 当前实际在跑的 D1 钩子:webpush(iOS 微信内不可用)+ ClawBot 微信桥(单机 47.84.8.167,单点)。三通道没有统一的健康度视图,无法回答"我们每天真实触达多少人、哪个通道带回访"。

### 3.2 范围

1. **运维项(前置)**:发件域修复/更换(Resend 域名验证),恢复后摘 `EMAIL_DIGEST_PAUSED`;看门狗(briefing-watchdog)恢复对邮件分支的监控。
2. **触达健康度看板**(`/admin/metrics` 扩一屏或 `/admin/push` 扩展):按通道(email / webpush / weixin / feishu)给 绑定数、当日发送数、送达/失败数、点击回访(Umami `returning_visit` 交叉 source)。数据源:现有 `push_subscriptions`、digest 发送记录、Umami——**不新增采集,只聚合已有**。
3. **微信桥单点风险登记**:本期不重构,只在 `EXTERNAL_SERVICES.md` 补充故障预案(桥挂了→用户侧表现→恢复步骤),并在看板上给桥存活探测(现有 net-probe 模式复用)。

### 3.3 验收

- [ ] 邮件早报恢复发送,退信率 < 2%,打开率进看板
- [ ] 看板一屏回答:各通道绑定数 / 日触达 / 回访贡献
- [ ] 微信桥宕机 24h 内能从看板发现(不再靠用户反馈)

## 4. P0-3 情绪卡增长实验(裂变 P0)

> 完整方案见 `viral-growth-plan.md`,已定稿,本节只列执行契约与验收。方案定稿于 2026-07 初,承接能力(免登录加自选 + InstantTake 即时兑现)现已就位——**当前是承接质量最好的窗口**。

### 4.1 范围(严格 = 方案 P0,不扩)

| 项 | 说明 | 量级 |
|---|---|---|
| 情绪卡 OG 海报 | `@vercel/og` 单模板 + 中文字体内嵌 + 二维码;固定免责水印为模板不可编辑层 | M-L |
| 存量页 og:image | 先静态品牌图 | S |
| 自建短链 + 承接域隔离 | `ShortLink` 表(走 `/api/admin/init-db` 惯例)+ `/s/[code]` 302 + 归因 cookie;**必须独立子域/独立域名,不得用主域**(域名存亡风险,方案 §8.2) | M |
| 情绪卡承接页 | 复用首页情绪只读 + 顶部软 CTA(免登录加自选),不弹窗拦截 | M |
| 3 个埋点 | `share_card_generate` / `share_link_visit` / 复用 `register`+`add_watchlist` | S |

### 4.2 硬规则(方案已拍板,工程红线)

- 免责水印写死模板层,无删除入口;不提供用户自填文案;`showIdentity=false` 不可编辑。
- 卡面文案过零数字闸(`hasSpecificMove`)+ 买卖黑名单。
- 复盘卡/清单卡/邀请体系一律不做(搁置项,不因"顺手"捎带)。

### 4.3 验收与决策规则

- 观测 4 周,北极星 = 绝对值薄漏斗:发卡人数 → 扫码数 → 扫码后加自选转化率。
- 基线参考(观测口径非承诺):发卡 >0 即证明假设成立;扫码 CTR 8-15%;扫码→加自选 10-20%。
- **决策规则(先定后跑)**:4 周后发卡人数为 0 或扫码→加自选 <3% → 判实验失败,增长资源转投 SEO(P2-4 已随 P0-1 落地),不追加卡类型;漏斗正向 → 进入方案阶段 B(个股利他卡)。

## 5. P1-1 复盘回写(M3)+ 历史同向统计上链

### 5.1 背景

- 五问中第 5 问(历史上类似链路是否有效)是唯一没兑现的:/track 有全局与分关系档统计(`statsOutcomesByRelation`),但不回流到具体推理链、关系档、insight 页。
- 这是**最难抄的资产**:AI 长文可抄,逐链逐关系档的复盘数据积累抄不走。晚开始一个月 = 少一个月数据。

### 5.2 范围

1. **回写数据层**:outcome 回填(现有 `api/cron/outcome`)扩展——按 `chainId × segment × relation` 聚合历史同向统计,落固定聚合表(避免页面现算)。
2. **上链展示**:insight 页(链级 daily + 事件专篇)的热力行/映射行,挂"历史同向统计"角标:「过去 N 次类似触发,该环节次日同向 X/N(历史统计·非预测)」;样本 < MIN_SAMPLE 显示"样本不足·观察中",不显示百分比。
3. **股票页**:关系档旁挂该股历史触发-同向记录入口(数据同源)。

### 5.3 合规红线(2.1-W3 口径延续)

- 禁词「有效率」;只叫**历史同向统计**;必带"历史统计·非预测"。
- 绝不换算成胜率/收益/准确率;绝不进对外分享素材(复盘对外卡是方案已判定的合规自杀点)。

### 5.4 验收

- [ ] 聚合表每交易日随 outcome cron 更新,insight/股票页读表不现算
- [ ] 样本不足态、无数据态诚实展示,无假 0、无空白掩盖
- [ ] 埋点:`backtest_badge_expand{page,chain_id}`——验证用户是否真的在意历史(反哺 P2-2 与 /pro 分层)

## 6. P1-2 池外票降级档(miss → 选题信号)

### 6.1 背景

- 池 202 只,池外票加自选直接出局("冷门票直接出局",onboarding 文档自认)。`relation_miss` 是 aha 头号杀手,但目前 miss 只是告警,不产生任何资产。

### 6.2 方案

1. **任意 A 股代码可加自选**:池外票给诚实降级档——行情 + 「该股暂未纳入产业链图谱」+「已登记,纳入后你会第一时间看到它的链上位置」;不给 LLM 现编关系(铁律 2:宁缺勿编)。
2. **miss 聚合选题看板**:`/admin/metrics` 加"池外票被加次数 Top N";扩池/扩链决策从"拍脑袋"改为读这张表 + `stocks_filter_use.chain_id` 分布 + 追问中出现的池外概念。
3. **兑现闭环**:某票被纳入后,对曾添加它的用户(有推送绑定的)发一条「你之前加的 XX 已纳入 XX 链」——登记过的期待必须兑现,这也是留存钩子。

### 6.3 验收

- [ ] 池外票可加、展示诚实降级态,`relation_miss` 语义拆分为 `miss_out_of_pool` / `miss_quiet`(原义保留)
- [ ] 选题看板上线,下一次扩池决策引用其数据
- [ ] 纳入兑现推送跑通至少一次

## 7. P1-3 验证点跟踪·轻量版

### 7.1 背景

- 验证点(800G/1.6T 订单、HBM 价格、液冷渗透率……)是全站已铺开的静态展示;它天然是**跨日持续的关注对象**,但产品没有利用——安静日(自选无触发)用户没有回访理由。
- /pro 意向候选第一条就是"自选链路深度追踪与提醒":先做免费轻量版验证需求,数据即付费版底料。

### 7.2 方案(轻量版边界)

1. 用户可在股票页/insight 页对验证点点「关注这个验证点」(免登录,同 watchlist 本地+登录合并模式)。
2. 每日管线生成时,若当日事件/公告命中某验证点(结构化匹配为主,LLM 判定为辅走护栏),对关注者推「你关注的验证点有进展:XX」;无进展不推(反焦虑,不造日更压力)。
3. 不做:自定义提醒条件、盯盘频率设置、历史进展时间线(付费候选,留给分层)。

### 7.3 验收

- [ ] 埋点 `verify_point_follow{point,chain_id}` / `verify_point_push_click`;
- [ ] 4 周观测:关注渗透率(自选用户中 %)与推送点击回访——两个数字直接进 /pro 月度复盘(P2-3),决定该能力进付费深度版还是砍掉

## 8. P2(条目制,过 P0/P1 后排期)

- **P2-1 insight 分级审核**:多链扩张前置。低风险 daily(无新映射、无方向翻转、护栏全绿)走抽审,新增映射/方向变化强制全审;抽审命中率达标后按 M1 拍板 D5 议 `INSIGHT_AUTOPUBLISH`。依赖 P1-1 的质量数据。
- **P2-2 置信度校准复盘页**:「标 high 的跳,历史同向是否显著高于标 low 的」——methodology 之后又一个别人不做的信任放大器。纯读 P1-1 聚合表,S-M 量级。
- **P2-3 pro 意向月度复盘机制**:每月固定产出一页(可进 /admin):`pro_interest`/`subscribe_intent` 分能力计数、点击者画像(watchlist 规模/回访频次)、当月结论(哪条候选升/降)。**另立项提醒:若付费在 6 个月规划内,收费+个股解读的法律意见(PRODUCT-CORE §7 硬前置)现在就该启动,不等产品 ready。**
- **P2-4 事件页 SEO 结构**:并入 P0-1 实施(见 2.3),此处仅追踪收录与自然流量数据。
