# StockTell 2.0 · 产品说明

> 收尾文档 1/4(负责人 2026-07-04 拍板产出;5 交易日稳定后终审)。团队必读的产品定位。

## 一句话
StockTell 是 **AI-native 的产业链理解工具**——从一件全球大事,推演出它会影响中国哪些产业链和股票,并给出每一跳依据。
**不是**新闻聚合、**不是**行情看板、**不是**荐股 / 喊单工具。长期愿景 = AI 时代的 Bloomberg。

## 产品公式(= 验收标准)
`事件输入 × 产业链图谱 × 多跳推理 × 资产映射 × 证据验证`
核心动作 = **多跳推理**(不是单跳"英伟达涨→A股AI涨"):事件 → 沿哪些环节传导 → 国内哪些票 → 每跳依据 → 历史是否有效。

## 三条铁律(硬边界)
1. **绝不做新闻聚合**——只收事件不堆新闻,必须推演到"为什么重要/影响哪条链/传导到哪/国内映射/依据/历史是否有效"。
2. **绝不输出无依据结论**——每个判断能回溯到事件/数据/公告/财报/关系边/复盘;无强证据处标"待验证/低置信"。
3. **绝不做交易指令**(定位铁律)——不输出买/卖/目标价/涨跌预测;个股永远是"关系分级的说明性示例",不是"推荐买入"。

## 用户主路径闭环
**首页(昨晚海外发生了什么 / 今天传导到哪条链 / 哪些直接映射哪些情绪 / 今天验证什么)
→ insight(因果链解释)→ /stocks(产业链股票地图,链→环节→关系→市场→自选筛选)
→ stock(产业链节点页:所属链/环节/关系档/为什么/验证点/触发源映射/历史统计)
→ watchlist(我的自选今天哪些被事件触发、是 direct/indirect/sentiment 哪种)
→ track(推理复盘·关系验证率)。**

## 关系词汇(全站统一,Phase 3 退双轨后无强/中/弱)
`触发源 / 直接映射 / 间接映射 / 情绪映射 / 弱映射 / 待验证` —— 每档含义见公开页 **/relations**。
证据状态前台标签:**已接入披露源 / 部分待核验 / 待补来源**(不显英文档 verified,避免误读成"已确认受益")。
历史联动只做**历史同向统计**(不叫"联动有效率"),必带"历史统计·非预测"。

## 合规姿态
不喊单 / 不荐股 / 不预测涨跌;"受益"→"关联";关系标"研究框架梳理·非确认";AI 输出挂"不构成投资建议"。
收费 + 个股解读上线前需一纸法律意见(主体 / 律师另立项)。详见 `docs/PRODUCT-CORE.md`。

## 内核 = 关系数据模型,不是 UI
难抄的是"事件库 + 产业链图谱 + 结构化关系模型(StockChainRelation)+ 每跳 references + 置信度 + 资产映射 +
历史复盘 + 自选关联"这套系统。见 [`2.0-relation-model.md`](2.0-relation-model.md)。
