# insight 真实数据生产管线 · 设计拍板稿(v1)

> **北极星(负责人 2026-07-03 定):先证明 StockTell 每天真的能"Tell",再去优化它 Tell 得漂不漂亮。**
> 因此 M1 的唯一验收 = 连续 10 个交易日,每天早上有"当日产业链推理"自动产出、人审、上线。文字糙没关系,断更才是失败。

## 0. 一个重要前提:每天能 Tell 的"地板"已经在跑

今天线上已有:07:01 cron 自动产出 8 条四段式事件推理 + 链级今日判断(chain-take)+ 首页因果链卡,全自动、有兜底、断供告警。
**管线要做的不是从 0 到 1,而是把 Tell 变"厚"**:从"事件条目+一段链判断"升级为"结构化 ReasoningChain(热力/逐跳依据/references/复盘回写)",且每天真实生产而非手工样板。

## 1. 产出物形态(拍板点①)

**建议:链级每日推理为主 + 事件专篇按触发。**

| 产出物 | 频率 | 内容 | 消费方 |
|---|---|---|---|
| 链级每日推理(daily) | 每链每交易日 1 份 | 固定骨架:今日触发/今日判断/环节热力方向/A股映射变化/今日风险/references | 首页因果链卡、链页、详情页"今日区" |
| 事件专篇(event) | 触发式,预计每周 1-3 篇 | 完整 ReasoningChain(ai-infra 1.0 模板结构) | 详情页、事件卡深读、分享 |

不做"每条异动一篇"——那会退化成新闻流(铁律 1)。

## 2. 管线七步(现有资产复用度标注)

1. **事件抓取**:复用 `findMovers`(美股异动≥2%,已在产)。阶段 2 加博查定向检索(官方公告/发布会/财报),复用 `bocha.ts` 零幻觉红线:搜不到=不写。不自建爬虫。
2. **事件归类**:复用 `CHAIN_EDGES`(359 条真实供应链边,带强度+依据)+ stocks 板块图谱 → 事件映射到 链/环节/A股;strength 强/中/弱 → 直接映射/间接映射/情绪映射(与 relation.ts 同一语系)。
3. **ReasoningChain 生成**:LLM **分段生成 + JSON schema 强校验**(复用简报 JSON_SPEC 模式,绝不让模型一次写长文);四段式口径+全量禁词已在 prompt;置信度默认只能给"中/低",「高」只有人审能提。
4. **references 绑定**:每跳博查检索真实来源(标题/URL/发布日期/supports 支撑哪一跳),URL HEAD 实测可达;检索不到 → 该跳标"推理假设·待验证",**绝不编链接**。
5. **人审**:草稿落库(draft)→ 飞书推卡片(要点+审核链接)→ admin 审核页(改文案/调置信/发布/打回)。
6. **发布**:published → 首页卡/链页/详情页 ISR 读库。
7. **复盘回写**:复用 BriefingOutcome 体系,映射标的 N 日表现回填该 insight 的"历史是否有效";联动有效率同步 /track。

## 3. 数据模型

新表 `insight_docs(id, slug, chainId, date, kind: daily|event, payload JSON, status: draft|published, reviewNote, createdAt/updatedAt/publishedAt)`。
ai-infra 种子保留为模板骨架;详情页优先读库、无则回种子。建表走 init-db 惯例。

## 4. 质量护栏(全自动,人审之前跑)

- schema 校验失败 → 重试 1 次 → 弃 + 飞书告警(不产垃圾等审)
- 禁词 lint(PRD §9.2 全清单)+ 具体涨跌数字红线(`hasSpecificMove` 复用)
- references URL 可达性实测
- **同图谱检测**:连续 3 天热力方向 diff=0 → 告警(防退化成"按类别检索预制图谱"——PRODUCT-CORE 红线:两类事件产出同一张热力图,产物不成立)

## 5. 排期(每步独立可验收)

- **M1(2-3 个工作日)**:ai 链 1 条,全链路跑通(生成→审→发→上页面)。**验收 = 连续 10 个交易日每天 08:00 前有当日已审推理上线。**
- **M1.5**:数据中心电力链、AI 应用链接入(链配置化,加链零工程)——与"详情页"优先级自然衔接:每条新链的首篇=人工精修的骨架(即详情页内容),之后每日由管线刷新。
- **M2(+2-3 天)**:事件专篇 + references 自动绑定。
- **M3**:复盘回写 + 抽审模式(人审修改率 <20% 连续 2 周 → 降为抽审)。

## 6. 成本与运行

每天 LLM 约 15-25 次(fast 档为主,分段+校验重试)+ 博查约 20-40 次;月成本估 <¥100,无新增外部服务。挂 07:01 主 cron 后串行(300s 内装得下,超了拆独立 cron,已有先例预案)。
