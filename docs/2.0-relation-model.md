# StockTell 2.0 · 关系模型说明

> 收尾文档 2/4。P1 产业链关系数据结构化的技术说明。设计稿见 `prd-chain-relation-model.md`。

## 三层架构(硬边界:每日管线关系【绝不】直接污染静态关系库)
| 层 | 内容 | 有效期 | 数据源 |
|---|---|---|---|
| **staticRelations** | 人工核定、长期有效 = `src/data/chain-relations.ts`(只吃审阅台 diff 回灌) | 长期 | manual/insight |
| **dailyRelationSignals** | 每日管线当天事件信号(骨架已建、层未落地) | 短期(当天) | pipeline |
| **relationReviewQueue** | 多次命中待人工沉淀/剔除(骨架已建) | 过渡 | pipeline→manual |

## relationResolver = 唯一读入口
`src/lib/relation-resolver.ts`。全站(/stocks、stock、watchlist、track、Dashboard 图谱)都走它,解"改一处漏几处"。
- `resolveRelationsForCode(code)` / `resolvePrimary(code)` / `resolveInChain(code, chainId)`。
- 输出 `ResolvedRelation`:`relationType`(长期档,只来自 static)+ `todaySignalStrength`(今日强度,来自 daily,**独立字段**)+ `resolvedSource`(static/daily/review)。
- **硬规则:daily 不自动提升 relationType**(高同向率≠升 direct);要调档必须走 reviewQueue 人工审。

## StockChainRelation 字段(`chain-relations.ts`)
| 字段 | 含义 |
|---|---|
| `relationType` | 六档:trigger/direct/indirect/sentiment/weak/candidate |
| `chainId` / `segmentId` | 所属链 / 环节(环节必须在 `segment-registry.ts` 在册) |
| `reason` | 人话解释(克制,不许"龙头/受益"无验证点) |
| `verificationPoints` | 四段式:订单 / 客户 / 收入占比 / 毛利率(该去核实什么,不是已受益) |
| `references` | 法定披露入口(深/北市巨潮、沪市上交所公告检索;**URL 不自产**) |
| `evidenceStatus` | verified / partially_verified / needs_review(定义见下) |
| `triggerGroup` | trigger 分组(ai-infra/ai-application/data-center-power/semiconductor…),不再一类 |
| `confidence` / `source` | 置信 / 来源(insight/manual/chain) |

## relationType 六档(定义 + 前台标签)
direct 直接映射 · indirect 间接映射 · sentiment 情绪映射 · weak 弱映射 · trigger 触发源 · candidate 待验证。
adapter = `relationTypeToDisplayBadge()`(relation-rank.ts),唯一"relationType→展示徽章"映射。公开说明 /relations。

## evidenceStatus 定义(前台不显英文档,走 EVIDENCE_LABEL)
- `verified` → **已接入披露源**:有稳定一手披露入口 + 业务入口高置信;**不代表**具体订单/收入已核。
- `partially_verified` → **部分待核验**:有源、业务方向相关,数字待核。
- `needs_review`/missing → **待补来源**:无源或证据不足。
- 硬约束:direct 必须有 references + verificationPoints;indirect 至少 references 或 evidenceStatus。

## 数据源分工
- 核定关系:`insight-chains.ts` mappings(insight 源)。
- 审阅升级:`chain-relations-audit.generated.ts`(从 `chain-relations-review-v2-audited.csv` 生成,勿手改)。
- 证据层:`direct-evidence.ts`(13 direct 手写)+ `indirect-evidence.generated.ts`(44 indirect 环节模板)。
- 环节 enum:`segment-registry.ts`(ai-infra + data-center-power 标准环节)。
- 触发源分组:audit 的 TRIGGER_CLASS。
