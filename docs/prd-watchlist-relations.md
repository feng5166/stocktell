# PRD · 自选股闭环:和我相关结构化关系卡(P1)

> 来源:需求原在《首页改版 PRD》§6.4「和我相关」+ 拍板⑨数据口径;本文整理为独立执行契约。
> 状态:**第一版已实现(097c0ee,预览待验收)**,本 PRD 标注「已实现 / 待确认 / 后续增强」供 review。
> 优先级:管线 > **自选股闭环(本 PRD)** > 因果链详情页 > P1/P2 打磨。

## 1. 背景与目标

首页 P0 已从"今日简报"变成"今日产业链推理台",但「和我相关」还只是"按自选筛选出的简报条目"。
P1 目标:把「和我相关」从**内容筛选**升级为**个人盯盘入口**——用户一眼看到"我的每只票属于哪条链、今天有没有被全球事件影响、是直接还是情绪映射、接下来该验证什么"。

**核心心智**:不是"今天哪些新闻跟我有关"(事件视角),而是"我的每只票今天怎样"(持仓视角)。

## 2. 三态(P0 已做空态,P1 做「有自选」态)

| 状态 | 展示 | 状态 |
|---|---|---|
| 未登录 | 「登录后添加自选股…[登录并添加]」 | P0 已做 |
| 已登录无自选 | 「添加你的自选股…」+ 搜索框 | P0 已做 |
| **有自选** | **结构化关系卡(本 PRD)** | **P1 已实现** |

## 3. 关系卡:数据口径(拍板⑨,已实现)

**不逐日逐股打 LLM**——静态映射 + 今日事件叠加:

- **股票 → 链身份**:`lib/watch-relation.ts` 服务端算全 A 股池的精简 map(链/环节/关系三档/验证点),传客户端本地查。零额外请求,不把 insight 全文拖进客户端包。
  - 环节:`stocks.ts` 的 sector → `chains.ts` segments(命中不到落「其他链上环节」兜底)。
  - 关系:`insight` 人工核过的分级优先(`relationForCode`),没核过用环节默认档(`segment.defaultRelation`);**前台统一三档**(直接映射/间接映射/情绪映射,弱映射归并入情绪映射)。
  - 验证点:`segment.verifyTemplate`(与管线 mappingsDelta 同一份模板,单一来源)。
- **今日事件叠加**:客户端用已有的当日简报条目(items)判断每只自选股今天是否被点名(triggerCode 命中 或 beneficiaries 含它)。
- **影响强度**:= 命中它的条目里最高影响力(高/中/低);未命中 = 无(不显强度)。
  - ⚠️ **影响强度只表示"产业链关系强弱 + 事件相关度",不表示投资收益预期**(§7 合规)。

## 4. 关系卡字段(已实现)

每只自选股一张卡:

| 字段 | 来源 | 已实现 |
|---|---|---|
| 股票名 + 入口 | STOCK_MAP;点击 → /stock/[code] | ✓ |
| 所属链 · 环节 | watch-relation map | ✓ |
| 关系类型(三档) | insight 核定 / 环节默认档 | ✓ |
| 影响强度 | 命中条目最高影响力 | ✓ |
| 今日触发事件 | 命中它的简报条目标题 | ✓ |
| 一句话解释 | **按关系档模板化**(见§6 待确认) | ✓(模板) |
| 需要验证什么 | segment.verifyTemplate | ✓ |

**分区**:header「你的自选里,今天有 X 只被全球事件影响」→ 被点名的票卡片区 → 「其余 N 只今日无直接事件(仍显示链身份)」折叠。

**位置**:「和我相关」区内,早报(MorningBrief)之后、相关事件流(CardFeed)之前——层次=人话早报综述 → 我每只票的链身份与今日状态 → 相关事件详情。

## 6. 负责人定稿(2026-07-03,4 调整已实现)

1. **一句话解释保持模板化**,不做逐股 LLM(拍板⑨延续)。逐股定制留后续增强。
2. **前台「影响强度」→「今日触发」**:去掉"影响"字样(避免暗示股价影响),chip 统一显示「今日触发」,强弱仅用颜色深浅体现(供排序/视觉),并加免责:**「今日触发」= 你的票今天被产业链事件点名,强弱仅表示事件相关度,不代表股价影响或收益预期**。
3. **非覆盖自选股必须展示**「暂未纳入当前产业链覆盖」,不能直接消失——放最后「暂未覆盖」折叠区。
4. **一句话解释去掉股票名**,只留环节解释 + 验证点。

## 6.1 排序规则(定稿,已实现)

1. 今日被事件点名的股票排最前;
2. 被点名股票内部按**今日触发强度**排序(高 > 中 > 低,取命中条目最高影响力);
3. 同强度下按关系类型:直接映射 > 间接映射 > 情绪映射 > 弱映射;
4. 未被今日事件点名但**已覆盖**的自选股 → 「其余自选」折叠区;
5. **未纳入覆盖**的股票 → 最后的「暂未覆盖」折叠区。

## 7. 合规(硬边界,已守)

- 关系类型明确表示**产业链关系**,不表示投资建议(标签就是"映射",非"推荐")。
- **影响强度 ≠ 收益预期**:文案用"影响强/中/弱",指关系强弱+事件相关度。
- 验证点是"该看什么公开信息",不是操作指令。
- 无任何买卖/目标价/涨跌预测。全站禁词清单同样适用。

## 8. 验收标准

**功能**:
- [ ] 有自选时展示结构化关系卡,每卡含 关系类型 + 需要验证什么(§6.4.7 硬要求)
- [ ] 关系类型与 insight 核定数据一致(中际旭创=直接映射、海光信息=情绪映射…)
- [ ] 验证点与 segment 模板一致
- [ ] 影响强度 = 命中条目最高影响力;未命中不显强度、归入「其余 N 只」
- [ ] 非本链池自选不误显
- [ ] 零额外请求(不新增 API,不拖 insight 进客户端包)
- [ ] 无买卖/操作语言;影响强度不被读成收益

**已实现验证(本地 CDP 注入自选实测)**:中际旭创(直接映射/光模块/影响中)、北方华创(直接映射/半导体设备/影响强)、海光信息(情绪映射/未命中→其余)。关系=insight 核定、验证点=环节模板,数据与渲染全对。
